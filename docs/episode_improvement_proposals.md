# Episode 结构改进方案讨论

> 日期: 2026-05-20
> 状态: 头脑风暴，待选方案

---

## 一、现状分析

### 当前 Episode 流程

```
reset():
  1. 随机选干扰类型 (9选1)，固定不变
  2. 生成第1个含干扰脉冲

step() × 8:
  每步都是独立的:
    - 收到一个新脉冲 (同干扰类型，新的随机噪声/相位)
    - agent 选算法 + 参数
    - 抗干扰 → 算 SINR 改善 → reward
    - 生成下一个新脉冲
  done = True (step 8 之后)
```

### 核心问题

| 问题 | 具体表现 |
|------|---------|
| **8步无状态依赖** | 每步收到的新脉冲和上一步选什么算法/参数完全无关 |
| **最优策略退化为静态映射** | 对某种干扰，最优动作永远是 (固定算法, 固定参数) |
| **GAE 时序信用分配无用** | reward 只取决于当前步动作，不需要跨步回溯 |
| **Buffer 同质化** | 8条数据 jammer_onehot 相同，动作大概率相同 |
| **CPPO 优势被浪费** | CNN 每步重新提取特征，但学到的是同一映射 |

### 等价模型

当前设计等价于: **每 episode = 1 个分类+回归问题 × 8 次独立采样**

## 二、改进方案

### 方案 A: JSR 渐进增强 (推荐)

**思路**: 每个 episode 内 JSR 从低到高递增，模拟干扰逐渐加强的对抗过程。

```
Episode:
  Step 1: JSR = 0 dB  (弱干扰，容易处理)
  Step 2: JSR = 2 dB
  Step 3: JSR = 4 dB
  Step 4: JSR = 6 dB
  Step 5: JSR = 8 dB
  Step 6: JSR = 10 dB (当前默认)
  Step 7: JSR = 12 dB
  Step 8: JSR = 14 dB (强干扰，需要精确参数)
```

**为什么有效**:
- 步骤间有了依赖: 低 JSR 下学到的粗略策略 → 高 JSR 下需要精细调参
- CPPO 优势体现: 不同 JSR 下最优参数不同，CNN 可以从信号中感知干扰强度
- stdPPO 用固定参数，高 JSR 时可能失效 → 拉开差距
- 物理意义清晰: 电子战中干扰功率确实会动态变化

**实现改动**:
- `environment.py`: step() 中按步数计算 JSR 并传给干扰器
- `config.py`: 新增 `jsr_range = (0, 14)` 配置
- 干扰器 generate() 已支持 JSR_dB 参数，无需修改

**风险**: JSR 太低时抗干扰前后 SINR 差距太小，reward 信号弱

---

### 方案 B: 干扰类型中途切换

**思路**: Episode 中途切换干扰类型，agent 需要快速识别并调整策略。

```
Episode:
  Step 1-4: 干扰类型 A (随机选)
  Step 5-8: 干扰类型 B (随机切换)
```

**为什么有效**:
- 引入时序依赖: step 5 开始环境突变，agent 需要识别变化并调整
- 强化 one-hot 的局限: 如果只靠 one-hot，切换后还需要一个 step 才能看到新 one-hot
  - 但实际上 one-hot 在每步都是正确的（环境给 state 时就包含当前干扰的 one-hot）
  - 所以这个方案的时序依赖主要在"上一个动作不再有效"的 reward 信号上

**问题**:
- 对 stdPPO 来说，one-hot 变了就能立刻切换策略，切换本身不难
- CPPO 的 CNN 信息优势不明显（one-hot 已经告诉了干扰类型）
- 物理上不太合理（实际对抗中干扰类型通常不会突然完全改变）

**结论**: 次优方案，可以作为 A 的补充

---

### 方案 C: 多脉冲联合处理 (M > 1)

**思路**: 生成 M 个脉冲（当前 M=1），agent 需要跨脉冲积累信息后决策。

```
Episode:
  Step 1: 收到脉冲1，选抗干扰参数 v1
  Step 2: 收到脉冲2 (新随机样本)，基于历史选 v2
  ...
  Step 8: 收到脉冲8，基于之前7步经验选最终参数 v8
  Reward: 后 N 步的平均 SINR 改善
```

**为什么有效**:
- 多脉冲积累是雷达信号处理的标准做法
- agent 可以学到"前几步探索参数空间，后几步用最优参数"的策略
- CPPO 可以从多个脉冲样本中提取更准确的干扰特征

**问题**:
- 当前雷达参数 M=1（单脉冲），改为 M>1 需要改 RadarEnvironment
- 训练时间增加（多脉冲生成和匹配滤波）
- 奖励设计更复杂（怎么衡量"探索"的价值？）

**结论**: 方向正确但实现复杂，可作为长期目标

---

### 方案 D: 连续对抗 (Jammer-Adaptive)

**思路**: 干扰器也是智能的——它会根据抗干扰效果调整自己的参数，形成博弈。

```
Episode:
  Step 1: 干扰用默认参数 → agent 选抗干扰 → SINR=X
  Step 2: 干扰调整参数(使SINR更差) → agent 需要适应 → SINR=Y
  ...
```

**为什么有效**:
- 真正的时序博弈，每步都依赖对手的上一步动作
- 这是最接近真实电子战的模型
- CPPO 的信号分析能力在此场景下价值最大

**问题**:
- 需要实现"智能干扰器"（额外的 RL agent 或规则系统）
- 双重 RL 训练极不稳定，工程量巨大
- 论文方向可能过于宏大

**结论**: 研究价值高，但工程复杂度也最高，建议作为长期方向

---

### 方案 E: 简化 Episode 为单步 (baseline 改进)

**思路**: 既然当前 8 步本质上是 8 次独立采样，不如承认这一点，改为每 episode 只做 1 步，但每 episode 换不同的干扰类型。

```
Episode (1步):
  1. 随机选干扰 + 随机 JSR ∈ [0, 14] dB
  2. 生成脉冲
  3. agent 选算法 + 参数
  4. 抗干扰 → reward → done
```

**优点**:
- 最简洁，无冗余
- Buffer 天然多样（每个 episode 可能是不同干扰+不同 JSR）
- 训练更快（8 倍 episode 数）

**问题**:
- 放弃了序列决策的可能性
- PPO 的 GAE 在单步下退化为 TD(0)
- 不好发论文（没有"序列决策"的叙事）

| 时序依赖 | 强 | 中 | 强 | 最强 | 无 |

## 四、推荐路线

**首选方案 (用户原创)**:
- **马尔可夫状态转移模型**: 见 [jammer_markov_model.md](jammer_markov_model.md)
  - 干扰机根据抗干扰效果 r_t 动态切换状态 (5 态马尔可夫链)
  - 真正的时序博弈: agent 动作驱动干扰变化
  - 实现简单 (只改 environment.py)，效果显著

**短期 (与马尔可夫模型并行)**:
- **方案 A (JSR 渐进)**: 作为马尔可夫模型的增强 (状态升级时同步增 JSR)
- 同时改 CPPO 输入为频谱幅度 (FFT) 以增强信号特征提取

**中期**:
- **A + C 组合**: JSR 渐进 + 多脉冲积累，更接近真实雷达处理

**长期 (论文亮点)**:
- **方案 D**: 用训练好的 RL agent 替代马尔可夫规则，实现真正的智能干扰器

## 五、方案 A 实现细节 (草案)

### 改动文件

1. **`rl_framework/config.py`**
   - 新增 `jsr_start = 0`, `jsr_end = 14`
   - `steps_per_episode` 保持 8

2. **`rl_framework/environment.py`**
   - `step()` 中计算当前步的 JSR:
     ```python
     jsr = self.cfg.jsr_start + (self.cfg.jsr_end - self.cfg.jsr_start) * self.current_step / (self.steps_per_episode - 1)
     ```
   - 生成新脉冲时传入当前 JSR (需要修改 `generate_with_jammer` 接口)

3. **`unified_framework.py`**
   - `generate_with_jammer` 支持动态 JSR 参数

### 验证

- 跑 CPPO vs stdPPO 3×600 对比实验
- 预期: CPPO 在高 JSR 步骤上优于 stdPPO（因为可以调参），低 JSR 步骤两者相当
